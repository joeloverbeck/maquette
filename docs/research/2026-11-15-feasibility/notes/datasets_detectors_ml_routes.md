## 1. Anime face detection and landmark detection: what exists, how many landmarks, how accurate, how well on profile / three-quarter / manga line art

### Takeaway
Face and head *detection* on anime is a solved, well-licensed commodity (lbpcascade 2011, hysts 2021, deepghs YOLOv8 2023-2025). Face *landmarking* is not: the only maintained off-the-shelf model (hysts, 28 points, MIT) is explicitly "near-frontal", publishes no accuracy number and no training-data description, and its point set has no head-top, hairline, ear or pupil; the only anime/manga landmark model with published error figures (60 points, manga, 2018) fails on about 1 face in 5 and excluded profile faces by design.

### Cited Findings

**Detectors and landmark models**
- hysts/anime-face-detector: "an anime face detector with facial landmark estimation, implemented in plain PyTorch"; "The model detects near-frontal anime faces and predicts 28 landmark points." Detectors are Faster R-CNN and YOLOv3; landmark net is HRNetV2. The README reports no accuracy metric and does not describe the training data. Requires Python 3.12+, PyTorch 2.2.0+; mmcv/mmdet/mmpose are no longer runtime dependencies since v0.1.0 (code vendored from mmpose v0.29.0, mmdetection v2.28.2, mmcv v1.7.0, Apache-2.0). [P] — [hysts/anime-face-detector README](https://github.com/hysts/anime-face-detector)
- Same repo: created 2021-10-29, last push 2026-07-05, 547 stars, licence MIT. It is the only anime landmark project found that is still being maintained in 2026. [API] — [hysts/anime-face-detector](https://github.com/hysts/anime-face-detector)
- Landmark weights card: "An anime facial landmark model (HRNetV2-W18 with a heatmap head) that predicts 28 landmark points per face", 9.68M parameters, trained by the author in 2021 with mmpose; licence MIT; weights "are provided as is, without warranty of any kind, including with respect to the provenance of the training data." Training dataset is not stated. [P] — [hysts/anime-face-detector-hrnetv2 model card](https://huggingface.co/hysts/anime-face-detector-hrnetv2)
- The 28 points are grouped in the repo's demo notebook as: face bottom outline indices 0-4 (5 points), left eyebrow 5-7 (3), right eyebrow 8-10 (3), left eye top 11-13 (3), left eye bottom 14-16 (3), right eye top 17-19 (3), right eye bottom 20-22 (3), nose 23 (1), mouth outline 24-27 (4). There is no forehead/hairline/head-top point, no ear point and no pupil/iris point. [P] — [demo.ipynb in hysts/anime-face-detector](https://github.com/hysts/anime-face-detector/blob/main/demo.ipynb)
- kanosawa/anime_face_landmark_detection: "an implementation of deep cascaded regression for anime face landmark detection on Pytorch"; uses lbpcascade_animeface for the face box; `num_landmark = 24` in example.py; pinned to Python 3.7 / PyTorch 1.3; training data and accuracy not stated. [P] — [kanosawa/anime_face_landmark_detection](https://github.com/kanosawa/anime_face_landmark_detection)
- Same repo: last push 2019-11-16, 253 stars, no licence file. Unmaintained; legally all-rights-reserved by default. [API] — [kanosawa/anime_face_landmark_detection](https://github.com/kanosawa/anime_face_landmark_detection)
- nagadomi/lbpcascade_animeface: "A Face detector for anime/manga using OpenCV" (an LBP cascade XML); original release 2011; the README itself says the author's animeface-2009 has higher detection accuracy; no training description, no accuracy number. [P] — [nagadomi/lbpcascade_animeface](https://github.com/nagadomi/lbpcascade_animeface)
- Same repo: last push 2018-11-23, 1,983 stars, no licence file. Unmaintained. [API] — [nagadomi/lbpcascade_animeface](https://github.com/nagadomi/lbpcascade_animeface)
- Observed lbpcascade failure modes when used to crop Danbooru at scale: the cropper "centers its crops on the center of a face (like the nose)", cutting off ahoge, animal ears and twin-tails; errors included a 4-koma comic, multi-face images and "strange hydra-like heads". [P] — [Gwern, anime crop datasets](https://gwern.net/crop)
- deepghs `imgutils` (MIT, last push 2025-10-11, 430 stars) ships YOLOv8-based anime detectors as separate functions: `detect_faces`, `detect_heads`, `detect_eyes`, `detect_halfbody`, `detect_person`, `detect_hands`, plus censor/text detectors. [P] — [imgutils detect index](https://dghs-imgutils.deepghs.org/main/api_doc/detect/index.html); [API] — [deepghs/imgutils](https://github.com/deepghs/imgutils)
- deepghs face detector: trained with YOLOv8, versions v0/v1/v1.3/v1.4 in "s" and "n" sizes; the docs page gives its benchmark only as an image chart (no numbers extractable). [P] — [imgutils detect_faces docs](https://dghs-imgutils.deepghs.org/main/api_doc/detect/face.html)
- deepghs/anime_face_detection dataset ("face only, not the entire head"), licence MIT: v1.4 has 12,798 train / 622 test / 1,217 validation images; v1 (5,943 / 293 / 566) was "auto-annotated with hysts/anime-face-detector, then manually corrected". Bounding boxes only, no landmarks. [P] — [deepghs/anime_face_detection dataset card](https://huggingface.co/datasets/deepghs/anime_face_detection)

**Landmark datasets with annotation schemes and reported accuracy**
- "Facial Landmark Detection for Manga Images" (Stricker et al., arXiv Nov 2018): a 60-landmark scheme adapted from the 68-point iBUG model (eyebrows 5 each, eyes 10 each plus 1 pupil each, nose tip 1, mouth 10, chin contour 17); 5,505 Manga109-derived face crops filtered to 1,446 annotated images, 656 labelled twice. [P] — [ar5iv 1811.03214](https://ar5iv.labs.arxiv.org/html/1811.03214)
- Same paper, exclusions: "we decided to focus on frontal faces and therefore removed manga faces with a profile view"; faces under 80 px, and faces where both eyes were not visible (glasses, hair), were removed. [P] — [ar5iv 1811.03214](https://ar5iv.labs.arxiv.org/html/1811.03214)
- Same paper, accuracy: error is normalised by chin distance rather than inter-ocular distance because "Manga eyes proportions and sizes vary a lot"; a face counts as a failure if normalised error exceeds 0.0333, a threshold taken from the authors' own relabelling disagreement. Best model (two-stage Deep Alignment Network with augmentation): mean error 0.02935, failure rate 19.31%; without augmentation 0.03467 and 37.93%. Abstract: landmarks found accurately "in more than 80% of the cases". Stated weakness: "it is difficult to find the landmarks on drawings where the facial expressions are exaggerated". [P] — [ar5iv 1811.03214](https://ar5iv.labs.arxiv.org/html/1811.03214)
- The labels for that dataset are public as a single archive (`landmarksUser.7z`): "We made only the labels available"; images require Manga109 permission. Repo last push 2019-11-21, no licence file. No pretrained model was found in the repo page. [P]/[API] — [oaugereau/FacialLandmarkManga](https://github.com/oaugereau/FacialLandmarkManga)
- "Landmark Assisted CycleGAN for Cartoon Face Generation" (2019) reportedly hand-annotated about 17,920 anime faces at 128x128 (sourced from Getchu) with landmarks. [S] — [arXiv 1907.01424](https://arxiv.org/pdf/1907.01424)
- OccFace (arXiv Feb 2026) reportedly targets stylised/non-human character faces with a 100-point dataset ("Genie-Face") with per-point visibility, and notes that stylised character landmarking is less studied than real faces. [S] — [arXiv 2602.10728](https://arxiv.org/pdf/2602.10728v1.pdf)
- For scale: best real-photo landmark models on 300W are reported around 2.85-3.0 NME (inter-ocular). No equivalent public leaderboard for anime landmarks was found. [S] — [HyperAI 300W leaderboard](https://hyper.ai/en/sota/tasks/facial-landmark-detection/benchmark/facial-landmark-detection-on-300w)

**Face/head corpora without landmarks**
- iCartoonFace (2019/2020, iQIYI): 389,678 images of 5,013 characters with identity, bounding box, pose and "other auxiliary attributes"; no landmarks mentioned. Code repo MIT, last push 2021-06-25 (unmaintained). [P] — [arXiv 1907.13394](https://arxiv.org/abs/1907.13394); [API] — [iCartoonFace repo](https://github.com/luxiangju-PersonAI/iCartoonFace)
- Danbooru2019 Portraits: "n = 302,652 (16GB) 512px anime faces", cropped from solo SFW Danbooru2019 images with lbpcascade_animeface with widened margins; an earlier pass over about 2.8M Danbooru2018 images yielded "~700k faces". [P] — [Gwern, anime crop datasets](https://gwern.net/crop)
- Danbooru2019 Figures: "n = 855,880 images (248GB; minimum width 512px)" single-character crops made with the AniSeg detector. [P] — [Gwern, anime crop datasets](https://gwern.net/crop)
- Manga109 (2020 paper): 109 volumes by 94 authors, 21,142 pages, "the total number of annotations exceeds 500k" over frames, speech text, character faces and character bodies (bounding boxes, not landmarks). A revised annotation set, Manga109-v2026, was released from 2026-05-21. [P] — [arXiv 2005.04425](https://arxiv.org/abs/2005.04425); [Manga109 on Hugging Face](https://huggingface.co/datasets/hal-utokyo/Manga109)
- AnimeCeleb (ECCV 2022): 3,613 3D animation models rendered to 2.4M head images, 256x256 by default, 4 shader styles; each image carries a 20-dimensional pose vector (17 expression values + roll/pitch/yaw). Models were collected from DeviantArt and Niconi Solid; "we carefully confirmed the scope of rights and obtained permission from reachable authors". [P] — [ar5iv 2111.07640](https://ar5iv.labs.arxiv.org/html/2111.07640)
- AnimeCeleb repo status: notice reads "The dataset seems to be broken at the moment. I'll fix it and re-upload it later."; no licence file; last push 2025-03-10. [P]/[API] — [kangyeolk/AnimeCeleb](https://github.com/kangyeolk/AnimeCeleb)

**3D anime head/character reconstruction (possible indirect route to proportions)**
- PAniC-3D (CVPR 2023): single-view 3D reconstruction of anime character heads from portrait illustrations; introduces a Vroid 3D dataset of 11.2k character models with multiview renders, a ~1k Vtuber portrait set, and the AnimeRecon benchmark. [S] — [arXiv 2303.14587](https://arxiv.org/pdf/2303.14587). Repo: no licence file, last push 2023-06-04 (unmaintained). [API] — [panic3d-anime-reconstruction](https://github.com/ShuhongChen/panic3d-anime-reconstruction)
- CharacterGen (arXiv Feb 2024, revised Jul 2024): single image to 3D character via multi-view diffusion that canonicalises pose; authors "curated a dataset of anime characters, rendered in multiple poses and views". Repo Apache-2.0, last push 2025-04-11. [P] — [arXiv 2402.17214](https://arxiv.org/abs/2402.17214); [API] — [CharacterGen repo](https://github.com/zjp-shadow/CharacterGen)
- StdGEN (CVPR 2025): semantically decomposed 3D anime characters from one image, with "separated semantic components such as the body, clothes, and hair", about three minutes per character. Repo Apache-2.0, last push 2026-04-17. A follow-up "StdGEN++" appeared on arXiv in Jan 2026. [P] — [arXiv 2411.05738](https://arxiv.org/abs/2411.05738); [API] — [StdGEN repo](https://github.com/hyz317/StdGEN); [S] — [StdGEN++](https://arxiv.org/html/2601.07660v1)
- NOVA-3D (arXiv May 2024): full-body anime character 3D from non-overlapped front and back views; introduces the NOVA-Human multi-view dataset (size not on the abstract page). [P] — [arXiv 2405.12505](https://arxiv.org/abs/2405.12505)
- AniFaceGAN (NeurIPS 2022) is an *animatable* 3D-aware face GAN trained on "unstructured 2D images" with a parametric 3D face model for expression control; its abstract does not mention anime, landmarks, or explicit mesh output. [P] — [arXiv 2210.06465](https://arxiv.org/abs/2210.06465)
- Toon3D (2024) reconstructs cartoon/anime *scenes* (camera poses, point clouds) from geometrically inconsistent frames; characters are not its target. [P] — [arXiv 2405.10320](https://arxiv.org/abs/2405.10320)

### Inferences
- The hysts model is usable as the frontal-face measuring instrument, but its accuracy must be established by the developer: no NME is published, and the training data are undocumented. The fact that deepghs used it to bootstrap bounding boxes and then "manually corrected" them indicates the community treats its output as good-but-not-final.
- Because the 28 points stop at the jaw outline and eyebrows, any measurement that needs the top of the head (eye-line height on the head, face height to hairline, head height for head-count) cannot come from landmarks alone; it has to be combined with a head box (`detect_heads`) or a character/hair mask, both of which include hair volume and accessories rather than the cranium.
- Nothing found supports automatic landmarking of true profile or strong three-quarter views: the one maintained model says "near-frontal", and the one evaluated model removed profiles from its data. Profile-view proportions (nose projection, chin-to-neck angle, ear position) should be assumed to need manual annotation or a 3D proxy.
- Manga line art is the weaker domain. The only quantified result (2018) is ~80% success on frontal, >=80 px, both-eyes-visible manga faces, i.e. on an already-filtered easy subset.
- "AniFaceGAN" and "Toon3D" in the brief are not anime-character measurement tools (one is a human-face GAN, the other is scene reconstruction); the relevant 3D lines are PAniC-3D, CharacterGen, StdGEN and NOVA-3D. These all train on VRoid/MMD-style 3D avatars, so proportions recovered through them would be pulled toward the avatar-template distribution rather than toward hand-drawn practice.
- AnimeCeleb's rendered, pose-labelled heads could serve as a controlled test set (known yaw/pitch) for calibrating how a 2D landmarker's ratios drift with head rotation, if the download is repaired.

### Gaps
- No published NME/PCK for hysts/anime-face-detector on any labelled set, and no statement of its training data; I could not find either on the README, the model card, or via search.
- I did not find a public anime landmark dataset larger than the 1,446-image manga set that I could verify on a primary page (the ~17.9k Getchu set and the 100-point Genie-Face set are snippet-level only; availability and licence unverified).
- deepghs detector metrics (mAP/F1) exist only as chart images on the docs pages; exact numbers not extracted. Head and eye detector training-set sizes not checked.
- Sizes of CharacterGen's and StdGEN's training sets (often cited as "Anime3D"/"Anime3D++") were not on the abstract pages I opened; not reported here.
- The canonical Manga109 site (manga109.org) failed TLS verification on fetch; per-class annotation counts (face vs body boxes) were not retrieved.

## 2. Anime body pose / keypoints: datasets, models, real-photo estimators on anime, and whether head-to-body and limb proportions can be measured

### Takeaway
There are two usable keypoint resources for illustrated bodies: the anime-specific Bizarre Pose Estimator (4,000 Danbooru images, 17 COCO keypoints, AGPL code, single full-body characters only) and Human-Art (50k images incl. 2,500 "cartoon" and 2,500 "digital art", non-commercial), whose fine-tuned ViTPose/RTMPose checkpoints lift art-domain AP by roughly 14-23 points over COCO-only models. Head and shoulder keypoints are reliable; hips, knees, ankles and wrists are not (PCKh@0.5 of 0.63-0.73), and no keypoint scheme includes head-top, chin or sole, so "heads tall" must be assembled from keypoints plus boxes/masks.

### Cited Findings
- AnimeDrawingsDataset (2015): "`data/data.json` contains all the 2,000 examples", split 1,400 / 100 / 500; joints annotated by volunteers; images are downloaded from the web by script. No licence file; last push 2015-06-11 (unmaintained). [P]/[API] — [dragonmeteor/AnimeDrawingsDataset](https://github.com/dragonmeteor/AnimeDrawingsDataset)
- "Transfer Learning for Pose Estimation of Illustrated Characters" (Chen & Zwicker, WACV 2022): upgrades that dataset to 4,000 single-character illustrations with all 17 COCO keypoints and bounding boxes (ADD minus 57 removed images plus 2,043 new, chosen for varied poses, especially back-facing; split 3,200 / 313 / 487). Boxes are generated by the character segmenter, not hand-labelled. Note: 2,000 - 57 + 2,043 = 3,986, which does not equal the stated 4,000; the paper does not explain the difference. [P] — [ar5iv 2108.01819](https://ar5iv.labs.arxiv.org/html/2108.01819)
- Same paper, headline accuracy on its test set (OKS@50 / OKS@75 / PCKh@50 / PDJ@20): best model with new data 0.8982 / 0.7930 / 0.7866 / 0.8403; a COCO-pretrained R-CNN baseline 0.7584 / 0.6724 / 0.6960 / 0.7357; pretrained OpenPose 0.4922 / 0.4222 / 0.4447 / 0.4796. [P] — [ar5iv 2108.01819](https://ar5iv.labs.arxiv.org/html/2108.01819)
- Same paper, per-keypoint (OKS@50 / PCKh@50 / PDJ@20): nose 0.9466 / 0.9918 / 0.9897; eyes 0.9795 / 0.9928 / 0.9928; ears 0.9589 / 0.9836 / 0.9795; shoulders 0.9825 / 0.8973 / 0.9343; elbows 0.8655 / 0.7290 / 0.7916; wrists 0.7341 / 0.6263 / 0.6961; hips 0.9630 / 0.6704 / 0.7854; knees 0.8686 / 0.6643 / 0.7577; ankles 0.8090 / 0.6263 / 0.7105. [P] — [ar5iv 2108.01819](https://ar5iv.labs.arxiv.org/html/2108.01819)
- Same paper, caveats: illustrated characters have larger heads and eyes, which makes COCO-style metrics not directly comparable to human results; characters often fill more of the frame so bbox-normalised thresholds are looser; low hip PDJ is attributed to annotator ambiguity; the original dataset was mostly forward-facing (5.45% of images had a back-related tag); the system has no awareness of perspective. Chibi and occlusion are not evaluated. [P] — [ar5iv 2108.01819](https://ar5iv.labs.arxiv.org/html/2108.01819)
- Bizarre Pose Estimator repo: "this project is focused just on single full-body characters"; all foregrounds come from Danbooru (images fetched by ID from Danbooru2020); Docker recommended, non-Docker environment "untested". Code licence AGPL-3.0; dataset and weights licence not stated; 12 commits, last push 2025-02-03, 267 stars. [P]/[API] — [ShuhongChen/bizarre-pose-estimator](https://github.com/ShuhongChen/bizarre-pose-estimator)
- Human-Art (CVPR 2023): "50k high-quality images with over 123k person instances from 5 natural and 15 artificial scenarios", 2,500 images per scenario; scenarios include Cartoon, Digital Art, Sketch, Kids Drawing, Ukiyoe, Ink Painting. Annotations: boxes, 21 keypoints (17 COCO plus "left/right fingers and left/right toes"), self-contact points, text. [P] — [Human-Art project page](https://idea-research.github.io/HumanArt); [ar5iv 2303.02760](https://ar5iv.labs.arxiv.org/html/2303.02760)
- Human-Art per-scenario pose AP on validation, HRNet with ground-truth boxes, COCO-trained vs COCO+Human-Art-trained: Cartoon 37.6 vs 64.7; Digital Art 59.6 vs 74.4; Sketch 44.1 vs 73.1; Kids Drawing 40.8 vs 86.1. One-stage ED-Pose: Cartoon 22.2 vs 60.4. [P] — [ar5iv 2303.02760](https://ar5iv.labs.arxiv.org/html/2303.02760)
- Human-Art person *detection* on Cartoon with COCO-trained detectors: Faster R-CNN 8.8 AP, YOLOX 10.8, Deformable DETR 7.9, DINO 8.7 (val); Faster R-CNN jointly trained reaches 37.9. Artworks "suffer from more severe pose distortion and imprecise body shape due to artistic exaggeration." [P] — [ar5iv 2303.02760](https://ar5iv.labs.arxiv.org/html/2303.02760)
- Released Human-Art checkpoints, AP on Human-Art val with GT boxes, COCO-only vs COCO+Human-Art: ViTPose-S 0.507 / 0.738; ViTPose-B 0.555 / 0.759; ViTPose-L 0.637 / 0.789; ViTPose-H 0.665 / 0.800; HRNet-w48 0.557 / 0.769; RTMPose-l 0.564 / 0.753. No per-scenario breakdown on that page. Dataset is form-gated and for "non-commercial purposes"; repo code Apache-2.0, last push 2023-10-03. [P]/[API] — [IDEA-Research/HumanArt](https://github.com/IDEA-Research/HumanArt)
- SDPose (arXiv Sep 2025), zero-shot on Human-Art when trained on COCO only (AP / AR): RTMPose-L 56.4 / 59.9; HRNet-W48 55.7 / 59.5; Sapiens-1B 64.3 / 67.4; ViTPose-H 66.5 / 70.1; Sapiens-2B 69.6 / 72.2; SDPose 71.2 / 73.9. No per-style (anime/cartoon) numbers; its out-of-domain benchmark uses one style (Monet-like). The paper states pose models "exhibit limited generalization" to out-of-domain cases such as anime characters. Code promised "upon publication". [P] — [SDPose, arXiv 2509.24980](https://arxiv.org/html/2509.24980v1)
- X-Pose (IDEA-Research; inference code and checkpoints released 2023-11-01; publication venue not confirmed on the page): prompt-based detection of arbitrary keypoint sets (COCO 17, 300W-Face 68, hand 21, animal sets); trained on UniKPT, 226,547 images / 418,487 instances / 338 keypoints / 1,237 classes, which is "only for non-commercial research purposes"; training code not released per the TODO list. [P] — [IDEA-Research/X-Pose](https://github.com/IDEA-Research/X-Pose)
- DWPose is the pose model deepghs wraps for "Detect human keypoints in anime images" (`dwpose_estimate()`, outputs grouped as head/body/foot/hand1/hand2); the docs give no anime accuracy number. DWPose repo: Apache-2.0, last push 2023-12-12. ViTPose repo: Apache-2.0, last push 2025-12-25. [P] — [imgutils pose docs](https://dghs-imgutils.deepghs.org/main/api_doc/pose/dwpose.html); [API] — [DWPose](https://github.com/IDEA-Research/DWPose), [ViTPose](https://github.com/ViTAE-Transformer/ViTPose)
- ControlNet/ComfyUI practice: a pose-node description surfaced in search attributes DWPose failures on anime to COCO-only training ("big heads and long legs"), distinguishes detection failures (character missing entirely) from pose failures, and offers an anime-oriented `rtmlib_humanart` engine as the fix. A separate user report describes an anime ControlNet treating an OpenPose stick figure as line art. Both are single, unbenchmarked community sources. [S] — [ComfyUI Unblend Pose Engine node page](https://comfy.icu/node/UnblendPoseEngine); [Anima-LLLite discussion](https://huggingface.co/kohya-ss/Anima-LLLite/discussions/6)
- CoNR (IJCAI 2023): character-sheet-conditioned rendering trained on "over 700,000 hand-drawn and synthesized images of diverse poses", using "Ultra-Dense Pose" maps generated from 3D models and motions. Code MIT, last push 2023-08-24 (unmaintained). [S] for the size — [CoNR arXiv 2207.05378](https://arxiv.org/abs/2207.05378v4); [P]/[API] — [megvii-research/IJCAI2023-CoNR](https://github.com/megvii-research/IJCAI2023-CoNR)
- Prior art on measuring anime proportions is thin: one 2020 Symmetry (MDPI) paper compares US and Japanese character body proportions in head-heights (cute characters about three heads, fearsome about five); the rest of what search surfaced is drawing tutorials stating conventions (for example a 6.5-head baseline, chibi about 3 heads). [S] — [MDPI Symmetry 12(8):1261](https://mdpi.com/2073-8994/12/8/1261)

### Inferences
- COCO-17 (and Human-Art-21) contain no vertex, chin or heel/sole point. "Heads tall" therefore needs: (a) a head extent from a head box or head mask, (b) a figure extent from a full-character mask or ankle/toe keypoints, and (c) proof the figure is upright, uncropped and unforeshortened. Each of (a)-(c) is a separate model with its own error, and (a) measures head-with-hair, not skull.
- Reading the per-keypoint table as an instrument spec: head and shoulder points land within half a head-length about 90-99% of the time; lower-body and wrist points miss that tolerance in roughly 27-37% of cases. Because anime heads are large, "half a head-length" is itself a generous tolerance, so true lower-limb noise relative to limb length is worse than the PCKh figure looks. Leg-length ratios are obtainable only as population statistics with outlier rejection, not per drawing.
- Error sources that the cited work either names or does not test: foreshortening/perspective (the estimator has "no awareness of perspective"; 2D projected length is only a lower bound on drawn length); clothing and hair hiding hips, shoulders and knees (the paper flags hip ambiguity); chibi (untested anywhere I found); multi-character images (unsupported by Bizarre Pose; detector AP on cartoons is low for generic models); dynamic poses (the new 2,043 images were chosen specifically for pose variety, i.e. the benchmark is harder than a standing-figure subset would be).
- For a proportions corpus the right subset is the opposite of what the pose datasets optimise for: standing, front-facing, full-body, single character. Accuracy on that easy subset should be better than the benchmark averages, but this is unmeasured.
- The strongest currently downloadable general model for illustrated bodies appears to be a Human-Art-trained ViTPose-H (0.800 AP overall on Human-Art val with GT boxes), yet "Cartoon" remains the hardest of the art scenarios checked (HRNet 64.7 after joint training). Whether Human-Art "Cartoon" resembles Japanese anime/manga closely enough is unverified.

### Gaps
- No benchmark found that isolates anime/manga full-body pose accuracy by view (front/side/back), by chibi vs normal proportions, or by line art vs colour.
- Licence of the Bizarre Pose dataset annotations and model weights is not stated on the repo page; only the code is AGPL-3.0.
- DWPose/OpenPose accuracy on anime specifically: only the 2021 OpenPose baseline (OKS@50 0.4922) is quantified; I found no DWPose or RTMPose number on an anime-only test set.
- I did not verify whether the Human-Art-trained ViTPose/RTMPose weights carry the dataset's non-commercial restriction.

## 3. Part segmentation / parsing for anime, and character-sheet / turnaround / settei datasets

### Takeaway
Character-vs-background matting is mature (SkyTNT, Apache-2.0 code; Bizarre Pose segmenter at IoU 0.93). True part parsing was a gap until 2026: the older option is Danbooru-Parsing (4,921 portraits, 17 face classes, no licence), and the significant new arrival is See-through (SIGGRAPH 2026), which releases a SAM-based body-part parser and a 19/23-part layer decomposer trained on 9,102 Live2D models. No curated public dataset of official model sheets (settei) was found; Danbooru's own tags are the practical source of turnarounds.

### Cited Findings
- SkyTNT/anime-segmentation: "high-accuracy segmentation for anime character" (foreground matting only, no parts); supports ISNet, U2Net, MODNet, InSPyReNet; training data is a merge of AniSeg and character_bg_seg_data cleaned "using DeepDanbooru first then manually"; no metrics, no stated licence for weights or dataset. - Bizarre Pose character segmenter (2021/2022): trained on 18.5k foreground samples (about 20x AniSeg's 945 images) composited over 5.8k Danbooru scenery and 2.3k stock textures; F-1 0.9472, precision 0.9427, recall 0.9576, IoU 0.9326, versus AniSeg F-1 0.5857 / IoU 0.6651 and YAAS SOLOv2 F-1 0.9061. Assumes one character per image. [P] — [ar5iv 2108.01819](https://ar5iv.labs.arxiv.org/html/2108.01819)
- Danbooru-Parsing ("Parsing-Conditioned Anime Translation: A New Dataset and Method", ACM TOG 2023): "4,921 densely labeled images across 17 classes" of anime portraits; the README label table actually lists 19 IDs (background, skin, l_brow, r_brow, l_eye, r_eye, eye_g, l_ear, r_ear, ear_r, nose, mouth, u_lip, l_lip, neck, neck_l, cloth, hair, hat). [P] — [arXiv HTML v1](https://arxiv.org/html/2602.03749v1)

### Inferences
- See-through's body-part parser is the first openly released tool that could turn "where does the hair end and the face begin; where are the eyes; where is the neck/torso boundary" into masks at scale. That directly attacks two measurement holes from sections 1-2 (face region excluding hair; head/neck/torso boundaries). But it reports no IoU, was trained on Live2D rigs (overwhelmingly front-facing, standing, modern VTuber-style characters), and was not shown on chibi, profile or monochrome manga, so it needs local validation before its masks are trusted as rulers.
- For face-shape (jaw contour) the plausible automatic route is a skin-class mask from Danbooru-Parsing's or See-through's parser, then fitting the lower contour, rather than the 5-point jaw outline from the landmark model. Neither parser has a published boundary-accuracy figure, and Danbooru-Parsing has no licence.
- For turnarounds, about 5k `turnaround` and 23k `reference_sheet` Danbooru posts are the realistic raw material. They are fan- and artist-made sheets mixed with official ones, need panel splitting (one image holds several views), and carry no view labels. A front/side-consistent proportion model therefore still needs manual pairing or a small hand-labelled set.
- Official anime production settei are copyrighted studio material; the absence of any curated open dataset of them is consistent with that, but I found no source that states the reason.

### Gaps
- Whether the Live2D-derived datasets behind See-through (9,102 models) and Bunraku (8,884 models) are downloadable, and under what terms, was not established; the See-through README mentions a data pipeline release but I did not confirm a dataset release.
- Licence of the See-through weights (as opposed to the Apache-2.0 repo) is not stated on the README.
- No per-part IoU for any anime part parser was found.
- I did not verify the reported CVPR 2025 Manga109 segmentation-annotation effort (SAM fine-tuned with LoRA in a human-in-the-loop pipeline) on a primary page; it surfaced only as a search snippet without a confirmed URL.
- Exact size of CoNR's character-sheet image set and its hand-drawn/synthetic split are not on either repo page.

## 4. Tagging metadata for stratifying by age / archetype / style, and how reliable it is

### Takeaway
Danbooru's human tags are high-precision but low-recall, which is the right failure mode for *selecting* strata (filter on presence, never on absence); the pool is large enough that strict filters still leave tens of thousands of images. Automatic taggers reach only about 0.47-0.51 macro-F1 over thousands of tags by their authors' own figures, so they are a recall booster and weak localiser, not ground truth; age and "archetype" strata are the least reliable because those tags are sparse and subjective.

### Cited Findings
- Danbooru2021: about 4.9M images, 162M tag instances, 498k defined tags, about 32 tags per image, covering 2005-2021; tags fall into copyright, character, artist, general and metadata categories; upload dates are in the metadata. [P] — [Gwern, Danbooru2021](https://gwern.net/danbooru2021)
- Tag quality, per the dataset's author: "almost all tags on images are correct, but the absence of a tag is often wrong"; he estimates tags are present less than 10% of the time they should be. [P] — [Gwern, Danbooru2021](https://gwern.net/danbooru2021)
- Live Danbooru post counts (public API, 2026-11-15), general tags: `1girl` 8,658,832; `1boy` 2,204,004; `solo` 7,257,219; `full_body` 1,331,569; `standing` 1,372,894; `upper_body` 1,238,833; `cowboy_shot` 882,699; `portrait` 150,173; `monochrome` 879,348; `lineart` 17,119; `chibi` 394,582; `from_side` 352,020; `profile` 187,596; `straight-on` 65,432; `aged_down` 91,622; `child` 83,236; `mature_female` 51,595. [P] — [Danbooru tags API, example query for chibi](https://danbooru.donmai.us/tags.json?search%5Bname%5D=chibi)
- WD EVA02-Large Tagger v3 (SmilingWolf): trained on Danbooru images with IDs modulo 0000-0899, validated on 0950-0999; last image ID 7220105, tags up to 2024-02-28; images with fewer than 10 general tags and tags with fewer than 600 images were filtered out; reported macro-F1 0.4772 at the P=R threshold 0.5296; licence Apache-2.0. [P] — [wd-eva02-large-tagger-v3 model card](https://huggingface.co/SmilingWolf/wd-eva02-large-tagger-v3)
- Successor and rival taggers, author-reported and not mutually comparable: Kagami-24k (fine-tuned from wd-eva02-large-v3) macro-F1 0.5138 vs 0.4728 for wd-eva02-large-v3 and 0.3592 for camie-tagger-v2 on 11,639 recent posts, with the author noting thresholds were swept on the test set; camie-tagger 58.1% micro-F1 / 31.5% macro-F1 over 70,527 tags; pixai-tagger-v0.9 about 13.5k tags on a 2025-01 snapshot (macro-F1 0.4481 in one third-party table); animetimm "dbv4-full" models around 0.60 macro-F1 on their own split. [S] — [Kagami-24k](https://huggingface.co/Redstonexs/kagami-24k); [camie-tagger](https://huggingface.co/Camais03/camie-tagger); [pixai-tagger-v0.9](https://huggingface.co/pixai-labs/pixai-tagger-v0.9); [danbooru-tagger-v1 comparison](https://huggingface.co/Redstonexs/danbooru-tagger-v1); [animetimm EVA02 dbv4-full](https://huggingface.co/Mooshie/eva02_large_patch14_448.dbv4-full)
- Bizarre Pose's own Danbooru tagger (2021): 837k images, 1,062 classes, F-2 0.4744 / F-1 0.4249, versus 0.2297 / 0.1910 for the earlier RF5 tagger. [P] — [ar5iv 2108.01819](https://ar5iv.labs.arxiv.org/html/2108.01819)
- deepghs `imgutils.validate` offers classifiers useful as strata or filters: `style_age` ("classifying anime style_age images into 7 classes": 1970s-, 1980s, 1990s, 2000s, 2010s, 2015s, 2020s; default model `mobilenetv3_v0_dist`), plus `classify`, `completeness`, `monochrome`, `portrait`, `teen`, `truncate`, `real`, `aicheck`, `bangumi_char`, `rating`. Accuracy is shown only as chart images. [P] — [imgutils style_age docs](https://dghs-imgutils.deepghs.org/main/api_doc/validate/style_age.html)
- Taggers can double as weak part localisers: See-through bootstrapped its part labels from Danbooru tags plus wd-eva02-large-tagger-v3 GradCAM++ maps before SAM-HQ refinement and human verification. [P] — [arXiv HTML 2602.03749v1](https://arxiv.org/html/2602.03749v1)

### Inferences
- Stratification by framing and view is well supported: `full_body`, `standing`, `solo`, `straight-on`, `from_side`, `profile`, `chibi` each have 65k to 7M positives. Even an intersection yielding 2-5% of `full_body` (1.33M) gives 25k-65k images, inside the 5k-50k target.
- Stratification by age/archetype is weak. `mature_female` (51.6k), `child` (83k) and `aged_down` (92k) are small against 8.7M `1girl`, which under the "absence is often wrong" rule means most adult-woman or child characters are untagged; filtering on these tags gives a biased sample of images where the trait was salient enough to tag (often exaggerated). A more defensible route is to stratify by character or copyright tag and attach external canon attributes (age, height), but that mapping was not researched here.
- Macro-F1 near 0.5 averages over thousands of rare tags; frequent visual tags (`chibi`, `monochrome`, `full_body`) will be far better than the average and rare/subjective ones worse. No per-tag figures were retrieved, so this is expectation, not evidence.
- "Competent drawings" has no direct tag. Proxies available in the metadata are `official_art` (560k), artist tags, score/favourite counts and the absence of `bad_anatomy`-type tags; all are popularity or provenance signals rather than draftsmanship labels.
- Era drift matters for "defaults": style_age or upload year should be a stratum, otherwise the statistics will be dominated by 2015-2025 illustration style (the bulk of Danbooru uploads).

### Gaps
- Per-tag precision/recall for the specific stratification tags (`chibi`, `mature_female`, `child`, `straight-on`, `profile`) for any tagger: not found.
- Numeric accuracy of deepghs `style_age` and `teen` classifiers: only charts, not extracted.
- Danbooru wiki definitions of the age/body-type tags and inter-annotator consistency: not researched.
- No independent, standardised 2025-2026 tagger benchmark was found; every figure above is self-reported on a different test split.

## 5. Licences and access: what can be used in an open-source project versus only for private measurement

### Takeaway
Tool licences are mostly permissive (MIT/Apache-2.0) with one copyleft exception (Bizarre Pose, AGPL-3.0) and several "no licence at all" research repos; the *data* are the constraint. Danbooru-derived corpora are relabelled CC0/MIT by their packagers but the images remain third-party copyrighted works; Manga109 is academic-only with no redistribution (Manga109-s permits commercial use of results under conditions); Human-Art, UniKPT and CoNR are non-commercial/research-only.

### Inferences
- A CC0 or MIT label on a Danbooru-derived dataset can only cover what the packager owns (metadata, packaging); it cannot relicense the artists' images. The safe reading for an open-source repository is: do not redistribute images or crops; publish only aggregate statistics (means, variances, quantiles of ratios) and the measurement code; keep the corpus and per-image annotations private or share them as image-ID lists. Aggregate proportion statistics are facts about many works rather than copies of any one, which is the lowest-risk artefact, but this is my reasoning, not legal advice, and the applicable law depends on the developer's jurisdiction.
- Usable inside an open-source (MIT/Apache-style) measurement pipeline without licence friction: hysts detector + landmarks, deepghs detectors/classifiers, SkyTNT segmentation code, WD tagger, DWPose/ViTPose code, vtracer. Usable but with caution: See-through (Apache repo, weights licence unstated, trained on commercial Live2D models).
- Private-measurement-only or needs care: Bizarre Pose (AGPL-3.0: running it privately is unproblematic; importing or linking it into the published tool would pull that component under AGPL); Human-Art- and UniKPT-trained weights (non-commercial data); Manga109 (academic institutions only, so a solo non-academic developer is limited to Manga109-s and cannot redistribute either); CoNR and AnimeCeleb (research-only or unlicensed); the no-licence repos (lbpcascade XML, kanosawa, Danbooru-Parsing model) which are widely used in practice but grant no explicit rights.
- The Danbooru20xx line being "in hibernation" for legal-climate reasons, and the absence of any disclaimer on the Hugging Face Danbooru2023 card, both signal that bulk access is tolerated rather than licensed; availability could change.

### Gaps
- No authoritative legal analysis specific to Danbooru-derived datasets was found; the Japan material is general law-firm commentary. US fair-use and EU text-and-data-mining positions were not researched.
- Whether Danbooru2023 on Hugging Face is gated, and its last update date, were not stated on the card as fetched.
- Potrace's licence (commonly described as GPL) and the terms of commercial vectorisers (Vectorizer.AI, Adobe Image Trace) were not verified on primary pages.
- Full English text of the Manga109-s agreement was not retrieved (gated); the conditions above are from search snippets of the official cards.

## 6. Vision-language models as measurers: can 2025-2026 multimodal LLMs locate facial landmarks on anime drawings well enough to replace a detector?

### Takeaway
No evidence found that they can, and the nearest evidence points the other way: on the main pointing benchmark a "hit" merely means the point falls inside the target's mask, and even so the best 2026 specialised pointing model scores about 71% and general frontier models of 2025 scored 30-47%. No benchmark of VLM landmark localisation on anime faces (NME or otherwise) was found at all.

### Cited Findings
- PointArena / Point-Bench (May 2025): 982 image-query pairs across Spatial, Affordance, Counting, Steerable and Reasoning; "A predicted point (xi,yi) is considered correct if it lies within the spatial support of some mask Mj" (i.e. region hit, not pixel distance). Default-prompt averages: GPT-4o 29.5%, Gemini-2.5-Flash 46.8%; LLaVA variants 4.8-17.4%; Molmo-72B was top, ahead of Gemini-2.5-Pro by a statistically insignificant 0.43 points; models trained with explicit pointing supervision consistently beat those without. The paper notes SAM-derived masks are "coarse and imprecise" at boundaries. [P] — [PointArena, arXiv 2505.09990](https://arxiv.org/html/2505.09990v2)
- MolmoPoint (Ai2, 2026-03-18): MolmoPoint-8B reaches 70.7% average on PointBench versus 68.7% for Molmo 2 (8B); the post argues text-coordinate pointing makes high-resolution grounding "brittle" and claims "better localization of small targets" from a coarse-to-fine design; no pixel-error figures are given. [P] — [Ai2 MolmoPoint blog](https://allenai.org/blog/molmopoint)
- FaceXBench (Jan 2025; 5,000 multiple-choice questions on face understanding, including a face-localisation category): GPT-4o 50.24% and GeminiPro 1.5 54.40% accuracy; multiple-choice, not coordinate output. [S] — [FaceXBench, arXiv 2501.10360](https://arxiv.org/html/2501.10360v3)
- A 2025 clinical study testing four multimodal LLMs (incl. ChatGPT-4o, Gemini 1.5 Pro) on 15 GAN-generated faces found low scores on facial *ratio* assessments, the best mean accuracy being 0.39 +/- 0.49 (Gemini 1.5 Pro), and framed landmark detection as a job for conventional computer vision. [S] — [MDPI J. Clin. Med. 14(10):3484](https://www.mdpi.com/2077-0383/14/10/3484)
- A 2025 technical report on GPT-4o found its pose-estimation behaviour inconsistent across instances and not conforming to a fixed format such as COCO-17, concluding current multimodal models "struggle with high-fidelity human pose estimation" without fine-tuning or templates (qualitative). [S] — [arXiv 2505.05501](https://arxiv.org/pdf/2505.05501)
- Where LLM-based keypoint localisation works, it is via *fine-tuned* specialist models (KptLLM/KptLLM++, LocLLM, CapeLLM, PoseLLM; PoseLLM reports 77.8 AP on COCO val), not zero-shot general chat models. [S] — [CapeLLM, arXiv 2411.06869](https://arxiv.org/html/2411.06869v2); [LocLLM, arXiv 2406.04659](https://arxiv.org/pdf/2406.04659); [PoseLLM summary](https://sotaverified.org/papers/posellm-enhancing-language-guided-human-pose)
- For comparison, dedicated real-face landmark models sit near 2.85-3.0 NME on 300W. [S] — [HyperAI 300W leaderboard](https://hyper.ai/en/sota/tasks/facial-landmark-detection/benchmark/facial-landmark-detection-on-300w)

### Inferences
- Measuring proportions needs landmark error of a few percent of face size. Point-Bench's success criterion ("inside the object mask") is one to two orders of magnitude looser than that, and models still miss 30-70% of the time. So "ask a VLM for the pixel coordinates of 28 landmarks on 50,000 drawings" is not supported as a detector replacement on current published evidence; cost and non-determinism would add to that.
- Roles where a VLM plausibly does help (unbenchmarked, to be tested locally): triage and quality control rather than metrology, e.g. "is this a single, standing, front-facing, uncropped figure?", "are both eyes open?", "is this chibi?", flagging detector failures for human review, or classifying part *types* (eye shape family, hairstyle) for the creator's categorical options.
- The trend (Molmo 2 to MolmoPoint, Gemini 2.5) is toward better pointing, and the Point-Bench numbers for the newest general models (2026 releases) were not found, so this conclusion should be re-tested with a 100-image hand-labelled anime set rather than assumed permanent.

### Gaps
- No published evaluation of any general multimodal LLM on anime/manga facial landmark coordinates (NME, PCK) was found; neither was one for real-face 300W-style NME.
- Point-Bench scores for late-2025/2026 frontier chat models were not found; the only 2026 figures located are for Molmo-family models. A search summary mentioned an unnamed 2026 submission at 77.2% overall, but I could not tie it to a specific page, so it is not cited above.
- The FaceXBench, clinical and GPT-4o items are snippet-level; I did not open those papers.

## 7. Competing routes that skip the parametric model: diffusion + vectorisation, direct SVG generation models, LLMs writing SVG

### Takeaway
None of the three routes yields what the parametric design is for (consistent, slider-editable, multi-view, animation-ready characters with stable part structure). Tracing produces dense, flat, colour-region paths; SVG-native models either exclude illustrations outright (StarVector) or emit 28k-token flattened path lists learned from traced diffusion images (OmniSVG); LLM-written SVG degrades systematically with complexity. The real ML competitor for "animatable 2D anime character" in 2026 is not SVG at all but raster layer decomposition toward Live2D (See-through, Bunraku), which still leaves rigging manual or immature and gives no parametric control.

### Cited Findings

**(1) Diffusion image, then vectorise**
- VTracer (visioncortex; MIT; 7,536 stars; last push 2026-11-13, actively maintained; install docs reference 1.0.0-alpha.4): converts raster images to SVG, handles colour ("has an image processing pipeline which can handle colored images"), "skips Potrace's expensive optimal-polygon search in favor of a fast, linear pipeline", and claims output "much more compact" than Illustrator's Image Trace because it stacks shapes and avoids shapes with holes. Modes: hierarchical `stacked` (default) or `cutout` ("a true seam-free mosaic"); curve fitting `pixel` / `polygon` / `spline`; clustering `color-cluster` / `bw` / `watershed`. [P]/[API] — [visioncortex/vtracer](https://github.com/visioncortex/vtracer)
- Potrace is described as supporting only black-and-white opaque images, suited to high-contrast line art. [S] — [Converting Images to Vector Graphics (P. Occil)](https://peteroupc.github.io/classic-wallpaper/docs/pixeltovector.html)
- This route is what a leading SVG model's own data pipeline uses for characters: OmniSVG's 0.4M-sample character subset is "Freepik & generated", the generated half made with FLUX plus a vector-style LoRA and "VTracer ... to perform near-instant vectorization of the generated images". Resulting character SVGs average 28k +/- 7.3k tokens (icons 2.2k +/- 0.9k; illustrations 8.1k +/- 3.3k). [P] — [OmniSVG, arXiv 2504.06263](https://arxiv.org/html/2504.06263v3)
- Layer-wise optimisation alternatives: LIVE ("Towards Layer-wise Image Vectorization", CVPR 2022 Oral; repo Apache-2.0, last push 2022-06-10, unmaintained) built on DiffVG (differentiable rasteriser; Apache-2.0, last push 2025-05-17). LayerTracer (arXiv Feb 2025, revised Aug 2025; repo MIT, last push 2025-04-01) characterises prior methods as yielding either "oversimplified single-layer outputs or optimization-induced shape redundancies" and instead has a diffusion transformer generate staged construction blueprints that are vectorised layer-wise with path deduplication. [API] — [LIVE](https://github.com/ma-xu/LIVE); [DiffVG](https://github.com/BachiLi/diffvg); [P] — [LayerTracer, arXiv 2502.01105](https://arxiv.org/abs/2502.01105); [API] — [LayerTracer repo](https://github.com/showlab/LayerTracer)
- Raster layer decomposition (the Live2D-oriented variant of this route): See-through outputs up to 23 inpainted RGBA layers as a PSD in roughly 74 s + 10 s on an RTX 4090, but its authors state it is not image-to-Live2D "at least, not yet" (no rigging, deformation meshes or physics), and that automatic decomposition favours semantic correctness over an artist's layer choices. Bunraku (July 2026) adds per-layer meshes and keypose displacements learned from 8,884 Live2D models, evaluated on 50 characters. [P] — [shitagaki-lab/see-through](https://github.com/shitagaki-lab/see-through); [arXiv 2602.03749](https://arxiv.org/html/2602.03749v1); [Bunraku, arXiv 2607.27348](https://arxiv.org/abs/2607.27348)
- Commercial native-vector generators: Recraft V4 (Feb 2026) and V4.1 (May 2026) are described by third-party guides as generating SVG directly from text rather than tracing, better at flat/geometric/illustrative styles than textures or gradients, sometimes producing very complex, hard-to-edit paths; "only model that natively generates production-ready SVG" claims are marketing-level. No independent comparison against Vectorizer.AI or Illustrator tracing was found. [S] — [MindStudio guide to Recraft V4.1 Vector](https://www.mindstudio.ai/blog/how-to-generate-editable-svg-files-recraft-v4-1-vector); [invideo Recraft overview](https://invideo.io/blog/recraft-ai-image-generator/)

**(2) Direct SVG generation models**
- StarVector (CVPR 2025; 1B and 8B; code Apache-2.0; repo last push 2025-11-07): VLM for image-to-SVG and text-to-SVG trained on SVG-Stack (2.1M train samples, average 1,822 +/- 1,808 tokens); serving examples use max lengths 8,192 (1B) and about 16k (8B). Stated limit: "StarVector models will not work for natural images or illustrations"; it excels at icons, logotypes, technical diagrams, graphs and charts. [P]/[API] — [joanrod/star-vector](https://github.com/joanrod/star-vector)
- OmniSVG (arXiv Apr 2025; built on Qwen2.5-VL; 4B and 8B; repo Apache-2.0, last push 2026-03-01): trained on MMSVG-2M = 1.1M icons (Iconfont), 0.5M illustrations (IconScout), 0.4M characters; "is able to parameterize SVGs exceeding 30k tokens"; supports text-, image- and character-reference-to-SVG. Stated limitations: it "generates tens of thousands of tokens for complex samples" (considerable generation time), and it "is only bounded by vector style image prompt and fails on natural images". Output structure is flat: preprocessing uses picosvg to remove "group" and "transform" and "we flatten the layered structure of the SVG script by concatenating different paths into a single command sequence". [P]/[API] — [OmniSVG, arXiv 2504.06263](https://arxiv.org/html/2504.06263v3); [OmniSVG repo](https://github.com/OmniSVG/OmniSVG)
- LLM4SVG (CVPR 2025; repo MIT, last push 2025-05-22): learnable semantic tokens for SVG components, trained on SVGX-SFT with "580k SVG instruction following data". It motivates itself by noting general LLMs' tokenised SVG handling "may result in hallucinations in vector primitive predictions" and that LLM training does not model path rendering order, causing occlusion between primitives. [P] — [LLM4SVG, arXiv 2412.11102](https://arxiv.org/abs/2412.11102); [API] — [LLM4SVG repo](https://github.com/ximinng/LLM4SVG)
- Chat2SVG (arXiv Nov 2024; repo describes it as CVPR 2025; no licence file; last push 2025-04-02): an LLM writes an SVG template from basic geometric primitives, then two-stage diffusion-guided optimisation refines paths; claims gains in fidelity, path regularity and semantic alignment plus natural-language editing. [P] — [Chat2SVG, arXiv 2411.16602](https://arxiv.org/abs/2411.16602); [API] — [Chat2SVG repo](https://github.com/kingnobro/Chat2SVG)
- Score-distillation family (per-prompt optimisation through a differentiable rasteriser): VectorFusion (arXiv Nov 2022; demonstrated "a range of styles including pixel art and sketches"); SVGDreamer (CVPR 2024; splits foreground objects from background, particle-based score distillation, claims better editability than baselines; repo MIT, last push 2025-05-01); NeuralSVG (arXiv Jan 2025; encodes the scene in a small network, dropout regularisation so each shape has "standalone meaning", motivated by other methods treating layer structure "as an afterthought"). [P] — [VectorFusion, arXiv 2211.11319](https://arxiv.org/abs/2211.11319); [SVGDreamer, arXiv 2312.16476](https://arxiv.org/abs/2312.16476); [NeuralSVG, arXiv 2501.03992](https://arxiv.org/abs/2501.03992); [API] — [SVGDreamer repo](https://github.com/ximinng/SVGDreamer)
- 2026 additions: LottieGPT (CVPR 2026; fine-tuned Qwen-VL; tokenises layered shapes, transforms and keyframes; trained on LottieAnimation-660K, about 660k Lottie animations plus 15M static Lottie files) generates editable vector *animations* from text or visual prompts. VAnim (May 2026) is reported as an LLM framework for open-domain text-to-SVG animation via sparse state updates on a persistent SVG DOM. InternSVG/SArena (31k-item benchmark incl. icons, illustrations, chemical formulas, animations) argues existing methods "struggle to generalize to long sequences and complex SVG content". [P] — [LottieGPT, arXiv 2604.11792](https://arxiv.org/abs/2604.11792); [S] — [VAnim, arXiv 2605.01517](https://arxiv.org/html/2605.01517); [InternSVG, arXiv 2510.11341](https://arxiv.org/pdf/2510.11341v2)
- A targeted search for a 2026 method producing layered, semantically grouped, riggable SVG *characters* found none; the closest hits were LottieGPT, LayerTracer, VAnim and (non-SVG) Bunraku. [S] — [LayerTracer, arXiv 2502.01105](https://arxiv.org/html/2502.01105v3)

**(3) General LLMs writing SVG directly**
- SVGenius (June 2025): 2,377 queries over understanding, editing and generation, 8 task categories, 18 metrics, built from real-world SVGs in 24 domains with complexity stratification; 22 models evaluated. Findings: "all models exhibit systematic performance degradation with increasing complexity"; proprietary models significantly outperform open-source ones; reasoning-enhanced training helps more than scaling; style transfer is the hardest capability. [P] — [SVGenius, arXiv 2506.03139](https://arxiv.org/abs/2506.03139)
- LLM4SVG's framing of the baseline: general models such as GPT-4 handle simple primitives (triangles, rectangles) but hit significant limits on complex graphics. A March 2025 review of LLM-based SVG processing reaches a similar picture across SVGEditBench, VGBench and SGP-Bench, with reasoning-enhanced models doing better. [S] — [LLM4SVG, arXiv 2412.11102](https://arxiv.org/html/2412.11102v1); [LLMs for SVG processing: a review, arXiv 2503.04983](https://arxiv.org/abs/2503.04983)

### Inferences
- Why route (1) fails the stated need. A traced character is a stack of colour regions with no part semantics, no shared topology between two characters or two views, and tens of thousands of path tokens (OmniSVG's 28k-token average is direct evidence of density). Nothing guarantees the same eye is the same path across frames or poses, so interpolation, rigging and slider control have nothing to attach to. Strength: unbeatable stylistic range and finish per single image. Multi-view consistency depends entirely on the upstream diffusion model.
- Why route (2) fails it. The one model that explicitly targets characters (OmniSVG) learned from flattened, group-stripped, largely auto-traced data, so it reproduces route (1)'s structure at higher cost; StarVector disclaims illustrations; the optimisation family (VectorFusion, SVGDreamer, NeuralSVG, Chat2SVG) is per-prompt, slow, and demonstrated on icons/simple illustrations, with "layers" meaning ordered shapes rather than a rig. LottieGPT is the first to model layered transforms and keyframes natively, but its corpus is UI/motion-graphics Lottie files, and I found no evidence of character rigs or cross-view identity. Strength: genuinely editable primitives for simple graphics; fast progress.
- Why route (3) fails it. Documented, systematic degradation with complexity; a full anime character is at the complex end. Strength: an LLM is good at *writing the generator code* and at simple parametric shapes, which is complementary to, not competitive with, a hand-built parametric system.
- The route that actually competes on "animation-ready 2D anime character" is raster layer decomposition into Live2D-style rigs. It is advancing quickly (two papers and a 5.7k-star tool within 2026), handles arbitrary art styles, and inherits Live2D's mature deformation runtime. Its gaps relative to a parametric creator: single view (2.5D head turn only), no continuous proportion sliders, per-character rather than systematic output, raster not vector, rigging quality still research-grade, and non-commercial/unclear terms on models and data.
- A parametric SVG system's defensible niche follows directly: guaranteed shared topology across all characters and views, exact editability, tiny files, deterministic output, and statistically grounded defaults. Its cost is the one ML routes do not pay: stylistic ceiling and authoring effort per part type.

### Gaps
- No controlled comparison of traced-SVG suitability for animation (path stability across frames, node counts on anime characters) was found; the "limits" above are inferred from data statistics and authors' own statements.
- Vectorizer.AI and Adobe Illustrator Image Trace / Text-to-Vector quality on anime art: no primary or independent source retrieved.
- Venues for OmniSVG, VectorFusion and NeuralSVG beyond their arXiv dates were not confirmed on the pages opened.
- OmniSVG's character-reference results are scored by GPT-4o (1-10) but no values were reported in the fetched text; actual quality on anime characters is unquantified.
- LottieGPT, VAnim and Bunraku are 2026 preprints/papers whose code availability and real-world output quality I did not verify.

## 8. Bottom line: for 5,000-50,000 drawings, which measurements are realistically obtainable automatically, with what noise, and which need manual annotation

### Takeaway
The measurement half is possible but only for a filtered slice and only as population statistics: frontal-face in-plane ratios (eye spacing, eye size, eye-to-chin, mouth/nose-to-chin, jaw width) and upper-body ratios (shoulder width relative to head) are obtainable automatically from 5k-50k images; anything needing the top of the skull, the lower body, a non-frontal view, or true shape (jaw curve) is either biased, noisy, or manual. No published accuracy figure exists for the key instrument (the 28-point anime landmarker), so a hand-labelled validation set of a few hundred images is not optional.

### Cited Findings
- Corpus supply is not the constraint: Danbooru carries 1,331,569 `full_body`, 1,372,894 `standing`, 7,257,219 `solo`, 65,432 `straight-on`, 394,582 `chibi`, 187,596 `profile` posts (2026-11-15), and tags that are present are almost always correct. [P] — [Danbooru tags API](https://danbooru.donmai.us/tags.json?search%5Bname%5D=full_body); [Gwern, Danbooru2021](https://gwern.net/danbooru2021)
- Face instrument: 28 landmarks = 5 jaw-outline, 3+3 eyebrow, 6+6 eye (3 top, 3 bottom each), 1 nose, 4 mouth; "near-frontal" faces only; no published accuracy; MIT. [P] — [hysts/anime-face-detector](https://github.com/hysts/anime-face-detector); [demo.ipynb](https://github.com/hysts/anime-face-detector/blob/main/demo.ipynb)
- Only quantified anime/manga landmark error: mean normalised error 0.029 of chin distance with a 19.31% failure rate on frontal manga faces of at least 80 px with both eyes visible; human relabelling disagreement on the same data defined the 0.0333 failure threshold. [P] — [ar5iv 1811.03214](https://ar5iv.labs.arxiv.org/html/1811.03214)
- Body instrument: 17 COCO keypoints; PCKh@0.5 nose 0.99, eyes 0.99, ears 0.98, shoulders 0.90, elbows 0.73, hips 0.67, knees 0.66, wrists 0.63, ankles 0.63; single full-body characters only; no perspective awareness; hip annotation itself ambiguous. [P] — [ar5iv 2108.01819](https://ar5iv.labs.arxiv.org/html/2108.01819)
- Silhouette instrument: character/background segmentation reaches IoU 0.93 (Bizarre Pose segmenter); SkyTNT's matting models are the maintained Apache-2.0 equivalent with no published metric. [P] — [ar5iv 2108.01819](https://ar5iv.labs.arxiv.org/html/2108.01819); [SkyTNT/anime-segmentation](https://github.com/SkyTNT/anime-segmentation)
- Part instrument: See-through's SAM body parser (19 parts) and Danbooru-Parsing (17-19 face classes on 4,921 portraits) exist, but neither publishes per-part IoU. [P] — [shitagaki-lab/see-through](https://github.com/shitagaki-lab/see-through); [zsl2018/StyleAnime](https://github.com/zsl2018/StyleAnime)
- Generic pose/detection models degrade badly on illustrated figures unless art-trained (cartoon person-detection AP about 8-11 for COCO-trained detectors; cartoon pose AP 37.6 rising to 64.7 with Human-Art training), so the detector stage, not only the keypoint stage, loses images. [P] — [ar5iv 2303.02760](https://ar5iv.labs.arxiv.org/html/2303.02760)
- General VLM pointing is at 30-71% on a region-hit criterion, far looser than landmark precision. [P] — [PointArena](https://arxiv.org/html/2505.09990v2); [MolmoPoint](https://allenai.org/blog/molmopoint)

### Inferences
All noise figures below are my estimates reasoned from the cited instrument specs; none is a measured result for this exact pipeline. "Per-image noise" means random error on one drawing; "bias" means a systematic offset that averaging over 50k images will not remove.

| Measurement | Automatic route today | Verdict | Expected noise / bias | Manual work needed |
|---|---|---|---|---|
| Eye spacing (inter-eye gap / face width) | hysts eye points + jaw-outline end points on near-frontal faces | Obtainable | Per-image error of a few % of face width if the landmarker performs like the 2018 manga model (about 3% of chin distance) on its successes; expect a 10-20% failure tail to be filtered by symmetry/confidence checks. Bias from residual yaw (narrows the far side) | Validation set only |
| Eye width, eye height, height/width ratio | 3 top + 3 bottom points per eye | Obtainable, noisier | Eye height is a short distance, so the same absolute pixel error gives a much larger relative error; half-closed/smiling eyes and thick lashes bias height. Filter on closed-eye/expression tags | Validation set; possibly relabel a few hundred eyes to learn a correction |
| Eye-line position on the head | Eye points + chin (jaw-outline midpoint) + head top from `detect_heads` box or hair/character mask | Partly: obtainable relative to chin-to-top-of-hair, not relative to the skull | Per-image noise moderate; **systematic bias** because the cranium top is hidden under hair in essentially every drawing and boxes/masks include hair volume, ahoge, hats, animal ears | Manual cranium-top (or artist-construction) annotation on a calibration subset, or redefine the parameter against hair-top |
| Face width / face height | Width at cheek from jaw-outline ends: yes. Height chin-to-brow or chin-to-eye: yes. Height chin-to-hairline: no (bangs) | Width and lower-face height obtainable; full face height not | As eye spacing for the obtainable parts | Hairline/forehead height is manual |
| Chin length (mouth-to-chin, nose-to-chin) | Mouth outline (4 pts), nose (1 pt), jaw midpoint | Obtainable on frontal faces, noisy | Short distances; anime noses are often a dot or omitted, so the nose point is the least trustworthy; open mouths shift the mouth points | Validation set; consider mouth-to-chin over nose-to-chin |
| Jaw / chin *shape* (pointed vs round, cheek fullness) | 5 jaw-outline points are too sparse; alternative is the lower contour of a skin mask from a face parser | Not reliably automatic | Parser boundary accuracy unpublished | Manual contour annotation of a few hundred faces, or use the 60-point manga labels (17 chin points, 1,446 faces, academic-licence images) as a seed |
| Head count of body (heads tall) | Head height from head box / chin + hair-top; figure height from character mask extent or nose-to-ankle keypoints; restrict to `solo` + `full_body` + `standing` + front-facing and reject crops | Obtainable in aggregate | My estimate: per-image error of several tenths of a head even after filtering, from hair/hat inflation of the head, heels/platforms and feet pointing down, bent knees, tilt and foreshortening; systematic downward bias in head count because head-with-hair exceeds skull height | Manual check of a few hundred figures to estimate the hair-inflation bias; chibi needs its own validation (no detector was tested on it) |
| Shoulder width (vs head width or height) | Shoulder keypoints (PCKh@0.5 0.90) | Obtainable for front-facing torsos | Keypoints mark joint centres, not the outer silhouette; torso yaw narrows it; capes, puffy sleeves and long hair occlude. Silhouette width at shoulder height (from the mask) is an alternative but includes clothing | Validation set |
| Leg length ratio (hip-to-ankle / height; thigh:shin) | Hip, knee, ankle keypoints | Marginal: aggregate only, with heavy outlier rejection | Roughly a third of hip/knee/ankle predictions miss a half-head tolerance; skirts and coats hide hips (even annotators disagree); any non-frontal leg is foreshortened, so projected length is a lower bound. Use the longer of the two legs and strict pose filters | Manual annotation recommended if this parameter matters; a few hundred clean standing figures hand-labelled may beat 50k noisy automatic ones |
| Arm length, hand and foot size | Elbow 0.73, wrist 0.63 PCKh; no reliable hand/foot extent | Poor | Arms are rarely straight and unforeshortened | Manual |
| Neck length/width, waist/hip width | No keypoints; only via body-part masks (See-through parser) | Unvalidated | Clothing dominates the silhouette | Manual or 3D-model proxy |
| Any profile or three-quarter proportion | No landmark model supports it | Not automatic | n/a | Manual, or derive from 3D avatars (with avatar-template bias) |
| Manga line-art versus colour illustration split | Same tools; `monochrome`/`lineart` tags for stratifying | Possible but riskier | Landmarker's training domain is undocumented; the only manga result is about 80% success | Separate validation subset for monochrome |

- Random noise is tolerable at this scale; bias is not. With 5k-50k samples per stratum the standard error of a mean ratio is negligible even at 10% per-image noise, so the binding problems are (i) systematic offsets (hair-inflated heads, yaw, foreshortening, clothing) and (ii) selection effects from filtering to detector-friendly images (front-facing, standing, simple outfits, modern style). Both must be measured against a hand-labelled reference; neither is reduced by adding more images.
- Ranges and correlations are harder than means. Slider *ranges* come from the tails of the distribution, which is exactly where detector failures concentrate (extreme proportions, chibi, stylised faces). Automatic tails should be treated as detector-limited until spot-checked; robust quantiles (for example 5th-95th) are safer than min/max.
- A realistic pipeline with permissive licences: tag filter (Danbooru metadata, optionally WD tagger for recall) then deepghs person/head/face detection, hysts 28-point landmarks, SkyTNT mask, a Human-Art-trained or anime-trained pose model, optionally the See-through part parser; reject by landmark symmetry (yaw proxy), box containment (crop check) and keypoint confidence; aggregate per stratum (era, chibi, sex tag, copyright). All components run locally; processing 50k images should be a matter of hours on one consumer GPU (my estimate, not benchmarked).
- Minimum manual investment I would plan for: about 300-500 images hand-annotated with the exact points the creator's parameters need (including cranium top, hairline, jaw contour, and heel/sole), used both to quantify each automatic measurement's bias and noise and to directly supply the parameters that have no automatic route. That set is also what a future fine-tune of the landmark model would need.
- Alternative or complementary source for multi-view and body parameters: measure 3D anime avatars or Live2D rigs (VRoid-derived sets of about 11k models, AnimeCeleb's 3,613 models, the roughly 9k Live2D corpora) where geometry and view are known. This removes detector noise but substitutes a different population (avatar templates made with slider-based tools, VTuber-style designs) for "competent hand-drawn anime/manga", and several of those sets are unlicensed, research-only or not confirmed downloadable.

### Gaps
- There is no end-to-end published study that extracted proportion statistics from a large anime corpus with these tools; the feasibility judgement is assembled from component benchmarks and is therefore untested as a whole.
- The accuracy of hysts' landmarker (the pivotal instrument) on colour illustration, on manga, and as a function of yaw is unknown; all face-row noise estimates above borrow from a different model on manga.
- No evidence was found on any tool's behaviour on chibi/super-deformed figures, which matter for the head-to-body slider's lower range.
- Head-with-hair versus skull-height bias has not been quantified anywhere I could find; it is likely the largest systematic error for both eye-line height and head count.
- Whether Human-Art's "Cartoon" and "Digital Art" categories are close enough to Japanese anime style for its pose checkpoints to outperform the anime-specific 2021 model on anime is not established by any source located.
